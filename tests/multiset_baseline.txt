# DELIBERATE DIVERGENCE (owner decision), not a defect to fix.
# EXIF / PSP creator-block / RealAudio Copyright (and kin) hold raw Latin-1
# bytes (© = 0xA9, ü = 0xFC). ExifTool emits them raw — invalid UTF-8 — because
# it does not transcode these charsets by default (Exif.pm ConvertExifText; the
# PSP/RealAudio readers pass bytes through). We decode UTF-8-or-Latin-1 to a
# readable ©/ü instead: returning U+FFFD (�) for real accented Copyright is a
# worse service than byte-parity with an invalid-UTF-8 reference. `extra` = our
# readable output, `missing` = the reference's raw byte. Do NOT "fix" with
# from_utf8_lossy — it regresses every real Latin-1 string in the wild.
